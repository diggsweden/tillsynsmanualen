Testfall

  • it()
  • it.with()
  • it.only()
  • it.skip()
  • describe()
  • beforeEach()

Ett testfall består av ett eller flera tester, eventuellt grupperade i samlingar (sviter). Ett test innehåller minst en förväntning. Om alla förväntningar uppfylls vid exekveringen är testet godkänt; om alla tester är godkända är testfallet eller samlingen godkänd.

Förväntningar, tester, samlingar och testfall representeras av klasser. För ökad läsbarhet och minskad komplexitet definieras ett antal bekvämlighetsfunktioner i _tests/functions.js, som alla testfall importerar. De möjliggör en Jest-liknande syntax.

Ett testfall är en specialiserad samling, så det kan ha en initieringsfunktion som körs före alla tester i hela testfallet.

Ett testfall realiseras av en JavaScript-modul. Namnkonventionen i Tillsynsmanualen är klass.test.js eller, för några modellklasser som är grupperade i samma modul, modul.test.js.

Test: it()

Ett test definieras med funktionen it(). På engelska ger det en läsvänlig, självdokumen­terande syntax som förklarar testets syfte, till exempel it("adds two terms"). Det är dock önskvärt att ha beskrivningarna på svenska, samtidigt som det enkla ”it” inte känns riktigt lika tydligt om det skulle översättas till den() eller det(). Resultatet blir tyvärr en osmaklig blandning av språken, med något försämrad begriplighet som följd.

it() anropar den statiska metoden TestRunner.addTest().

Syntax

it(description)
it(description, body)

Parametrar

description
En beskrivande text som förklarar vilken funktion testet verifierar. (Inte vad testet gör!)
body
En funktion som implementerar testet. Funktionen kan vara synkron eller asynkron. Om funktionen kastar ett undantag är testet underkänt, annars är det godkänt. Om ingen funktion anges är testet ”avvaktande”, det vill säga väntar på att implementeras. Det gör det möjligt att förbereda ett testfall med tester innan man börjar implementera dem.

Returvärde

Inget (undefined.)

Exempel

it("adds two terms", () => {
    expect(add(1, 2).toBe(3));
});

it("loads the content", async () => {
    expect(await load()).toBe(…));
});

it("is not yet implemented");

Testdata: it.with()

Det är möjligt att exekvera samma test flera gånger med olika uppsättningar testdata. Varje uppsättning data ska vara en vektor (Array) med ett eller flera värden i. Den angivna implementationen anropas en gång för varje element i vektorn och varje anrop har vektorns innehåll som parametrar.

Det går även att infoga testdata i beskrivningstexten som visas när testet exekverar, genom att ange värdets index (0-baserat) omgivet av ’{’ och ’}’; se exempel nedan.

it.with(), it.only.with() och it.skip.with() anropar den statiska metoden TestRunner.addTest().

Syntax

it.with(data)(description, body)

Parametrar

data
Testdata.
description
En beskrivande text som förklarar vilken funktion testet verifierar.
body
En funktion som implementerar testet.

Returvärde

Inget (undefined.)

Exempel

it.with(
    [true,  "on"],
    [false, "off"]
)("returns the state '{1}'", (state) => {
    fixture.setState(state);
    expect(fixture.getState()).toBe(state);
});

Singulärt test: it.only()

Ibland är det önskvärt att tillfälligt exekevera bara ett enda test i ett (eller flera) testfall. För att slippa kommentera bort alla andra testfall kan man därför märka ett test som det enda som ska utföras. Ramverket exekverar det första testet det påträffar med en sådan märkning.

Märkningen går att kombinera med testdata, till exempel it.only.with(…)(…).

it.only() och it.only.with() anropar den statiska metoden TestRunner.addTest().

Syntax

it.only(description, body)

Parametrar

description
En beskrivande text som förklarar vilken funktion testet verifierar.
body
En funktion som implementerar testet.

Returvärde

Inget (undefined.)

Överhoppat test: it.skip()

Ibland är det önskvärt att tillfälligt undanta ett test från exekvering. För att slippa kommentera bort koden kan man indikera att ett test ska hoppas över.

Märkningen går att kombinera med testdata, till exempel it.skip.with(…)(…).

it.skip() och it.skip.with() anropar den statiska metoden TestRunner.addTest().

Syntax

it.skip(description, body)

Parametrar

description
En beskrivande text som förklarar vilken funktion testet verifierar.
body
En funktion som implementerar testet.

Returvärde

Inget (undefined.)

Testsamlingar: describe()

En samling, eller testsvit, är en gruppering av tester med en gemensam beskrivning. En samling kan ha en gemensam initieringsfunktion som körs före varje test. En samling kan också innehålla andra samlingar.

describe() anropar den statiska metoden TestRunner.addCollection().

Syntax

describe(description, body)

Parametrar

description
En kort beskrivning av samlingen.
body
En funktion som implementerar samlingen; vanligen ett antal tester, eventuellt med en initieringsfunktion först.

Exempel

describe("Checks", () => {
    beforeEach(() => {…});
    it("checks this", () => {…});
    it("checks that", () => {…});
});

Initieringsfunktioner: beforeEach()

En initieringsfunktion körs före varje test i den samling där den är definierad. Initierings­funktioner används för att sätta upp testdata, så att varje test blir oberoende av andra tester.

beforeEach() anropar den statiska metoden TestRunner.addBeforeEach().

Syntax

beforeEach(init)

Parametrar

init
Initieringsfunktion att köra före varje test i samlingen.

Exempel

describe("Suite", () => {
    let fixture;

    beforeEach(() => {
        fixture = new Calculator();
    });

    it("computes sum", () => {
        expect(fixture.add(1 + 2)).toBe(3);
    });
    …
})
